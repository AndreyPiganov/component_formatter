# Компоновщик иллюстраций

Веб-сервис собирает редактируемые SVG-композиции из каталога векторных объектов. Можно ввести заголовок или метафору, перечислить названия объектов или собрать сцену вручную. Редактор поддерживает перетаскивание, поворот, пропорциональное масштабирование, дублирование, удаление и смену порядка слоёв.

## Запуск

Из корня репозитория выполните команду и откройте [редактор](http://localhost:8080).

~~~bash
docker compose up --build
~~~

nginx отдаёт React и проксирует запросы к API NestJS. Compose поднимает PostgreSQL, выполняет миграции Prisma сервисом `migrate` и запускает NestJS. Данные PostgreSQL хранятся в томе `postgres_data`. Папка `assets` монтируется в режиме чтения как источник импорта.

После изменения исходных файлов выполните `docker compose restart backend`. Корректный полный манифест обновляет каталог целиком. При ошибках отдельные корректные записи обновляются, а ранее загруженные варианты сохраняются. При отсутствии манифеста сервис использует каталог из PostgreSQL. Кнопка «Свой SVG» загружает файл в раздел «Мои SVG» текущей сессии. Его можно добавить вручную. Когда на холсте есть такой слой, редактор отмечает его присутствие и сохраняет результат как `personal-composition.svg`.

Для запуска на другой машине передайте `assets/catalog.json` и `assets/library/` отдельно от репозитория. Если порт занят, укажите `APP_PORT` в `.env` по примеру из `.env.example`.

## Короткая демонстрация

| Сценарий | Текст | Формат и палитра | Пример |
| --- | --- | --- | --- |
| По названиям | книга, лампа, ручка, папка (фон) | 1000 × 1000, лавандовая | study-and-ideas.svg |
| По метафоре | Музыка, приложение и решение головоломки | 500 × 500, бирюзовая | music-and-puzzles.svg |
| По названиям | кошелёк, монета, смартфон (фон) | 1200 × 630, персиковая | digital-wallet.svg |

Выберите режим, введите текст и нажмите **Собрать**. Перетащите объект, выберите его слой, измените угол и продублируйте его. Смените размер холста или палитру, затем нажмите **Скачать SVG**. Три примера и скриншот редактора `editor.png` находятся в локальной папке `assets/demo/`.

Автосборка применяет один коэффициент масштаба ко всем предметам с учётом их размеров в исходной библиотеке. Опорный размер предмета — его длинная сторона в детальном главном SVG, если этот вариант доступен. Компактные и фоновые варианты сохраняют пропорции своих контуров. Поле «Размер композиции, %» меняет размер всей подборки относительно центра холста. Потяните квадратную ручку в углу выбранного объекта, чтобы масштабировать композицию вокруг противоположного угла. Круглая ручка над объектом поворачивает его вокруг центра. Также можно зажать Ctrl (⌘ на macOS) и потянуть сам объект. Две кнопки в панели слоя отражают его по горизонтали и вертикали.

Масштаб просмотра можно менять над холстом сочетанием Ctrl + колесо или кнопками «−» и «+». На macOS также поддерживается ⌘. Кнопка «Вписать холст» возвращает весь лист в рабочую область. Формат SVG задаёт список размеров над холстом.

## Как устроен каталог

- Из векторного листа Figma выделены десять объектов. У каждого есть главный и монохромный варианты для двух размеров. При выделении сохранены исходные контуры, их атрибуты и порядок. Рамка каждого файла задана через viewBox по границам объекта.
- При запуске NestJS импортирует `assets/catalog.json` и SVG по относительным путям. Один предмет, например книга, хранится в `Component` с общими названием и тегами. `ComponentVariant` задаёт роль (`main` или `background`), детализацию (`detailed`, `simple` или `any`), источник, относительный путь к файлу и исходный текст SVG. Ключ варианта состоит из ID предмета, роли и детализации. Редактор и API используют прежние ID ролей, например `book-main`. Поле `componentId` в манифесте явно связывает варианты. Для прежних записей оно выводится из `id` удалением конечного суффикса соответствующей роли. Название и теги у вариантов предмета должны совпадать.
- React хранит слои как ссылки на объекты каталога и их трансформации. Размер холста определяет вариант исходника. При экспорте каждый слой становится группой в SVG с собственными идентификаторами внутренних ресурсов.
- Для обоих режимов подбора NestJS получает из PostgreSQL только идентификаторы и метаданные исходных объектов, доступных для выбранной детализации (включая универсальные варианты). Подбор по названиям учитывает названия и теги, разделённые запятыми, точками с запятой или переносами строк. Суффикс (фон) выбирает монохромный вариант. Без ключа OpenAI режим метафоры ищет связанные теги. При наличии OPENAI_API_KEY в .env NestJS передаёт модели заголовок, названия и теги доступных объектов. Ответ ограничен их идентификаторами. Размещение на холсте рассчитывает редактор.

### Как работает ИИ

В режиме метафоры NestJS выбирает из PostgreSQL метаданные доступных вариантов. Первый запрос в Responses API передаёт заголовок и описание функции `list_catalog`. Модель запрашивает инструмент, сервер проверяет имя и аргументы и возвращает список по `call_id`. Во втором запросе модель выбирает ID из этого списка, а сервер проверяет каждый ID. Исходные SVG остаются внутри сервиса. При ошибке или таймауте работает поиск по тегам. Режим подбора по названиям выполняется локально. По умолчанию используется `gpt-5.4`, модель задаётся переменной `OPENAI_MODEL`. Один успешный подбор по метафоре использует два обращения к API.

В бэкенде функциональные модули находятся в `backend/src/modules/`. Источник импорта читает файлы, а репозиторий библиотеки записывает и читает варианты через Prisma. Импорт выполняется одной транзакцией. Повторный импорт обновляет варианты по составному ключу. Сцены, загруженные через интерфейс SVG и пользовательские палитры хранятся в состоянии React до перезагрузки страницы. Для сохранения результата редактор экспортирует SVG.

Пример записи в массиве catalog.json.

~~~json
[
  {
    "id": "book-main",
    "componentId": "book",
    "name": "Раскрытая книга",
    "source": "Набор Figma",
    "tags": ["книга", "чтение"],
    "role": "main",
    "detail": "detailed",
    "file": "library/detailed/main/book.svg"
  }
]
~~~

Выберите слой и откройте «Цвета объекта». В каждой строке слева показан исходный цвет, справа — его замена в текущей схеме. Замена действует на выбранный экземпляр и сохраняет прозрачность. При выборе другой схемы используется та же позиция новой палитры. У фонового объекта доступны четыре фоновых цвета, у главного — все восемь. Переключатель «Роль объекта» появляется, если в каталоге есть парный вариант для текущего размера. Смена роли подставляет соответствующий SVG и его стандартные цвета.

Палитра импортируется как JSON через кнопку загрузки рядом с заголовком **Палитра**. Массивы задают четыре фоновых и четыре дополнительных цвета для главных объектов. Порядок соответствует позициям в исходной палитре Figma. Фоновые объекты и холст используют только фоновые цвета.

~~~json
{
  "name": "Моя палитра",
  "background": ["#D7CDF5", "#AA9BF0", "#7864D7", "#181817"],
  "objects": ["#F9ECB0", "#F9A3AA", "#FFE3E1", "#FFFFFF"]
}
~~~

## Разработка

Для запуска API и React на хосте нужен Node.js 24. Поднимите PostgreSQL, установите зависимости и примените миграции.

~~~bash
docker compose up -d --wait postgres
npm --prefix backend ci
npm --prefix frontend ci
npm --prefix backend run prisma:migrate
~~~

Запустите API и React в отдельных терминалах. Откройте редактор на локальном порту 5173. Vite проксирует API на локальный порт 3000.

~~~bash
npm --prefix backend run dev
npm --prefix frontend run dev
~~~

Для локального подключения к собственной базе задайте `DATABASE_URL` в корневом `.env`. По умолчанию хостовый NestJS и Prisma подключаются к PostgreSQL на порту `5433`. Порт и пароль для запуска через Compose задаются в `.env` по примеру из `.env.example`.

~~~bash
npm --prefix backend run prisma:validate
npm --prefix backend test
npm --prefix frontend test
npm --prefix frontend run build
~~~

AI-инструменты проекта включают Codex для реализации и проверок и опциональный OpenAI Responses API для подбора существующих объектов по смыслу.

Исходный код проекта хранится в [репозитории component_formatter](https://github.com/AndreyPiganov/component_formatter).
